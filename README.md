# drug-hansch-space

The published home explorer is in `site/`; there is no application build step.

The **DRD2 QSAR · validation** button in the home page's Hansch section opens a native overlay. It reads `site/data/qsar_drd2.json` only when opened and shows a conditional training-fit surface, scaffold-holdout predictions, 100 y-scrambles, a Williams plot, validation metrics and coefficient tables. The original 759-drug explorer can colour exactly matched compounds by applicability domain. All response values are pChEMBL.

The reproducible notebook in [drug-toxicity-qsar-prediction](https://github.com/DhruvMenon2003/drug-toxicity-qsar-prediction) generates the frozen export for human DRD2 (`CHEMBL217`), binding assays (`B`) and `Ki` only. Save its compact JSON to both `data/qsar_drd2.json` (source data) and `site/data/qsar_drd2.json` (published asset); the two files must be byte-identical. Do not hand-edit model metrics. Missing or incompatible exports produce an explicit unavailable state.

The displayed prediction and domain diagnostics come from the scaffold-training model. The separate all-data coefficient table is a descriptive post-selection fit. The surface holds other descriptors at training medians; it is not a claim that this target-grouped dataset is a congeneric series.

Check changes with `npm run check`, `npm run test:unit`, and `npx playwright test tests/e2e/qsar.spec.mjs`. The static checker retains its existing 8 MB cap on `site/`. GitHub Pages publishes that folder directly; no new page, framework or application bundle is needed.

## Read the workflow, then inspect an equation

Open **DRD2 QSAR · validation** on the home explorer. The workflow guide connects collection, structure identity, replicate aggregation, feature selection, validation and cache replay. Compound lookup, split/domain filters and the equation inspector work on the same frozen 250-compound export. An equation term is coefficient × descriptor value; its contribution is an algebraic decomposition, not evidence that changing that molecular property causes the predicted biological effect. The inspector uses the training model, while the separately labelled full-data fit is descriptive.

The model is **not predictive**: scaffold-test R² = −0.0898, five-fold scaffold q² = −0.2850 and LOO q² = 0.0714. Passing the 100-shuffle chance-correlation check does not overturn those results. Target-grouped compounds are not a congeneric series. This workflow makes the statistical reasoning and its limitations inspectable; it does not establish a molecular binding mechanism.

The [executed notebook](https://github.com/DhruvMenon2003/drug-toxicity-qsar-prediction/blob/be9bcd29a70b545ecc2420728f5e1206e084a809/curation/hansch_drd2.ipynb) and [audited outputs](https://github.com/DhruvMenon2003/drug-toxicity-qsar-prediction/tree/944a7e8717ea6bf85815cb1fa103bcd2c4ca2fd4/curation/results/hansch_drd2) are pinned to the tested revision. Follow an InChIKey through `dataset.csv`, `candidate_features.csv`, `features.csv` and `predictions.csv`; use the molecule/document identifiers and source structures to trace its measurements in `raw_activities.csv`. `selection.json`, `dropped.csv`, `feature_selection.json` and `provenance.csv` explain the transitions. The notebook embeds the calculations and downloads a SHA-256-verified frozen cache, so it does not depend on mutable API results for replay.

## Reproduce a single-assay QSAR pilot

The separate [single-assay notebook](notebooks/qsar/chembl3855278/assay_qsar_pilot.ipynb) follows frozen ChEMBL source records → explicit curation → five descriptors → grouped split → training-only scaling/Ridge fitting → held-out predictions and domain diagnostics. The [offline replay bundle and instructions](notebooks/qsar/chembl3855278/README.md) include source/decision ledgers, fixed recipe, exact splits, transparent JSON coefficients, predictions, hashes and an [executed notebook](notebooks/qsar/chembl3855278/assay_qsar_pilot.executed.ipynb). Source and derived tables retain their [dataset-specific ChEMBL licence and attribution](notebooks/qsar/chembl3855278/DATA_LICENSE.md).

This exploratory D2-binding pilot uses 80 eligible compounds from assay CHEMBL3855278: 57 training and 23 holdout compounds across six unseen scaffolds. Ridge holdout R² is −0.052 versus −0.077 for the training-mean baseline; **useful predictive skill is not established**. Labels are database-attributed experimental pKi, not independently verified laboratory measurements; complete paper-row mapping remains unresolved. It is not a general D2 predictor or a replacement for the frozen 250-compound model above. Replay runs separately from the explorer; the published app, connection policy and existing scientific artifacts are unchanged. Fresh Colab execution is not yet verified.

Download the [checked Excel workbook](notebooks/qsar/chembl3855278/exports/assay_qsar_pilot_public.xlsx) to inspect source records, curation, descriptors, predictions and validation together; its [QA receipt](notebooks/qsar/chembl3855278/exports/public_qa_receipt.json) records the checks and limitations. This is a static export: notebook replay regenerates CSV/JSON, but portable automatic XLSX regeneration is not yet established.

## Bio-Loom research and the scope of the emulation

Research checked **22 October 2026**. The intended reference is **BioByte's Bio-Loom**, the Hansch/Leo QSAR software, rather than unrelated projects named BioLoom or BioBloom.

| Primary evidence | What was verified | How it informs this explorer |
| --- | --- | --- |
| [Bio-Loom product description](http://www.biobyte.com/bb/prod/bioloom.html) and [BioByte/Dotmatics announcement, 5 April 2016](https://www.prnewswire.com/news-releases/dotmatics-partners-with-biobyte-to-offer-clogp-across-the-entire-dotmatics-platform-574592241.html) | Bio-Loom links CLOGP/CMR calculations, chemical-property records and QSAR datasets. | Connect the existing compound explorer to model data and its provenance. |
| [Official manual](http://biobyte.com/bb/manual/Bio-Loom_Manual.html), especially [QSAR lookup](http://biobyte.com/bb/manual/lessons/QSAR.html), [compound details](http://biobyte.com/bb/manual/lessons/Full_Compound_Details.html) and [name lookup](http://biobyte.com/bb/manual/lessons/Run_One_ClogP__Name_Lookup_.html) | Documented interactions include compound lookup, dataset selection, parameter/correlation tables and equation details. | Search the frozen compounds, filter split/domain status, and inspect the training equation and per-compound terms. |
| [C-QSAR manual](http://www.biobyte.com/bb/prod/qsarman2k.pdf), sections V and IX, and [worked QSAR search tutorial](http://www.biobyte.com/blqsar/index.html) | Discusses interpreting parameters, examining outliers and seeking independent support for mechanistic hypotheses. | Show validation failures and domain flags alongside the equation; distinguish statistical association from mechanism. |
| [Products and services](http://www.biobyte.com/bb/Prices_2.html) | Offers database packages, a ClogP DLL and a command-line product; the evaluation page asks users to obtain an evaluation licence. | No claim of an open-source licence or numerical compatibility with those products. |

The official [BL-1.7 evaluation ZIP](http://www.biobyte.com/downloads/BL-1.7.zip) was downloaded and its contents inspected with Python `zipfile`: 37,663,114 bytes, 226 archive entries (96 ordinary files excluding directory entries and macOS metadata), SHA-256 `f091e9856a5866096ed47cb57a275c0e7c3f8d753d7e0201c2b5311016cea461`. It contains `BIO-LOOM.exe`, supporting DLLs/data, HTML/Java editor support and readable Perl helpers `Support/approx_match/amatch.pl` and `Support/babel/pipeline.pl`. These support files are not the core Bio-Loom/CLOGP implementation. No core source release was found in the official download, linked documentation or focused public GitHub searches. This is a bounded search result, not proof that source is unavailable elsewhere. The vendor HTTP pages were readable; HTTPS fetches repeatedly failed.

Search branches included Bio-Loom/BioByte source, licence and manual queries; GitHub code searches for `"Bio-Loom" "BioByte"`, `"bioloom" "QSAR"` and `"biobyte" "CLOGP"`; and examination of the vendor download/manual links. Relevant GitHub hits were citations, benchmark data or integrations, rather than a verified Bio-Loom core source release. No downloaded program or helper was executed, and no vendor code, parameter database or artwork is redistributed in this repository.

This is a small independent implementation of the documented lookup → parameters → equation workflow, using our ChEMBL snapshot and existing JavaScript. RDKit's [Wildman–Crippen MolLogP/MolMR](https://www.rdkit.org/docs/source/rdkit.Chem.Crippen.html) are labelled as such; they are not BioByte CLOGP/CMR. Whole-molecule MolLogP is also not the classical substituent hydrophobic constant π. We do not emulate the proprietary fragment/interaction engine, licensed Masterfile/CQSAR databases, molecular editor or multi-target search. Those would exceed the one-target, one-notebook scope and require separate data/method validation.

### Additional user-supplied teaching reference

[Santiago Bolivar's Universal Interactive QSAR notebook](https://github.com/Sbolivar16/QSAR_Tools/blob/cf2514d10038252627d397d2164741077ff5d06f/QSAR_Universal_Interactive.ipynb) was inspected as source, without execution (30 cells; file SHA-256 `b161317e2ebe6287563dd08c226dabfa4ce18fb2821c064335358f508d68ffe2`). Its staged explanations, attrition report and output guide are useful presentation references for our workflow guide. We did not import its code or change our model to its classification/screening workflow.

Specific differences matter: its zero-based cells 10–11 do not select/filter `standard_units` before naming `standard_value` as `activity_nM`; cell 13 fits imputation, filtering and scaling before the split/CV in cell 14; cell 19 plots absolute probability distance from 0.5 under a Williams-plot title, rather than standardized measured residuals. Our strict nM eligibility/pChEMBL response, fold-local selection, scaffold holdout and measured-residual Williams plot remain unchanged. Inside-domain status does not establish reliability, and docking agreement alone would not validate predictive performance. This is a focused source review, not a runtime audit of that external notebook.
